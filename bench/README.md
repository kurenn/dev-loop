# dev-loop benchmark

Compares dev-loop **v0.1.0** against **v0.2.0**. The two versions differ in ways that need
different kinds of evidence, so the benchmark is split rather than run as one score:

- **Tier 1 — execution harness.** Most of what v0.2 changed is *correctness*, not quality.
  You do not need statistics to show that a command cannot be invoked or that
  `gh pr create` fails on a branch nothing pushed. Tier 1 runs each flow once per task and
  asserts binary facts about the resulting repository.
- **Tier 2 — gate isolation.** The most contested change is the quality gate. Tier 2
  replays a frozen corpus of artifacts through *only* the rater and the gate, with the
  loop removed entirely, so the rater prompt is the single variable. Dozens of cheap agent
  calls instead of dozens of full loops.

Tier 3 (end-to-end, blind-graded, hidden acceptance tests) is deliberately not built yet.
It costs dozens of full loop runs per arm and should only be paid for once Tiers 1 and 2
say it is worth it.

## Setup

```sh
bench/tier1/setup-app.sh          # builds the pristine Rails app + a bare origin
```

Ruby and Rails must be on PATH (`gem install rails`). The generated app lives in
`bench/.work/` and is gitignored: an ordinary Rails 8 app with a **gitignored
`config/master.key`**, a green 7-test minitest suite, and a small Project/Task domain.
Those three properties are what make the Tier 1 assertions meaningful.

## Tier 1

```sh
BENCH_STAMP=run1 bench/tier1/run.sh v0.1 t01-projects-write
BENCH_STAMP=run1 bench/tier1/run.sh v0.2 t01-projects-write
```

Each run clones the pristine app, gives the **main checkout** the gitignored
`master.key`, a prepared database and installed gems — simulating a developer's machine —
and points `origin` at a fresh bare repo. Then it invokes the flow under
`--plugin-dir bench/flows/<version>`, so both arms expose the same `/dev-loop` command and
differ **only in the skill body**. Both arms run on the same orchestrator model
(`BENCH_MODEL`, default `opus`) with the same task text.

### Assertions

| ID | Asserts | Why it discriminates |
|---|---|---|
| A1 | main checkout still on `main` and clean | v0.1 hands subagents no worktree path, and subagents inherit neither context nor cwd |
| A2 | a worktree was created | both claim to |
| A3 | that worktree has `master.key` and its suite runs green | `git worktree add` checks out tracked files only, so an unprovisioned worktree cannot boot |
| A4 | the worktree branch has commits | v0.1 never tells anyone to commit |
| A5 | the branch reached `origin` | v0.1 opens a PR from a branch nothing pushed |
| A6 | shipping was handled, not silently failed | the bench origin is a bare local repo, so a real PR is impossible by construction — passing means the branch got pushed *and* the run ended by saying what remains |
| A7 | no paid review ran while the suite was red | v0.2 adds a mechanical gate ahead of review |
| A8 | which phase artifacts exist | v0.2 persists `PLAN-CRITIQUE`, `REVIEW-round-N`, `RATING-round-N`, `LOOP_STATE`; v0.1 persists only `PLAN.md` |
| A9 | the diff stayed inside the plan's declared file ownership | v0.2-only; v0.1 declares no ownership |

Metrics recorded alongside: cost, token counts, wall clock, agent spawn count, spawn
models, tool histogram, diff size.

**A7 and A9 are best-effort and labelled as such in the output.** A7 reconstructs ordering
from the parent transcript, which does not contain subagent-internal tool calls. A9 parses
file paths out of `PLAN.md` prose. Treat both as signal, not proof.

### Known limitations

- **v0.2's plan checkpoint cannot be exercised headless**, so the v0.2 arm is run with
  `--auto`. Its highest-value safeguard is therefore *not* measured here, and Tier 1
  understates v0.2. Check it by hand, interactively.
- **The bench origin is a bare local repo**, not GitHub, so `gh pr create` cannot succeed
  for either arm. A6 measures graceful handling instead of PR creation. This is also how
  the benchmark surfaced a real gap in v0.2: `gh auth status` succeeding does not mean the
  repo has a GitHub remote.
- **Roundhouse and codex, if installed, are visible to both arms.** That is deliberate —
  it holds the environment constant — but it means Tier 1 measures the flows *as
  configured on this machine*, and codex runs cost OpenAI credits.
- **One run per pair is not a sample.** Tier 1 targets deterministic-ish binary failures.
  Anything that comes out mixed across runs belongs in Tier 2 or Tier 3, not here.

## Tier 2

```sh
BENCH_REPS=5 bench/tier2/replay.sh c01-api-pagination
```

A frozen case — `plan.md`, a diff, mechanical check output, adversarial review findings —
is sent to both rater designs, N times each, with no loop and no tools. The corpus is
generated by `seed.py` from one correct implementation plus seeded defects.

**The defects are all invisible to the test suite, on purpose.** A defect a failing test
would catch is caught by the Tier 1 mechanical gate and tells you nothing about the rater.
Tier 2 measures the gate of last resort: what gets through when the tests are green.

Three of the five defects also delete the test that would have caught them. That is not a
convenience — it is what actually reaches a reviewer. An implementer who inverts a page cap
and leaves its assertion in place produces a red suite, which Tier 1 catches; the variant
that survives to Phase 7 is the one where the assertion went too.

| Variant | Ground truth | Defect |
|---|---|---|
| `good` | should pass | correct, **shippable** implementation — not flawless, and a good reviewer should still raise things. Blocking it is a false positive |
| `authz_removed` | should block | the API base controller no longer requires a token |
| `page_cap_inverted` | should block | `?per_page=100000` returns 100000 rows |
| `nil_dereference` | should block | `show` raises on any project with a null description |
| `missing_acceptance_criterion` | should block | pagination state dropped from the response, and its test deleted with it |
| `coverage_removed` | should block | the `show` endpoint has no test at all |

### The two arms

`raters/v0.1.md` is the faithful reconstruction of what a v0.1 orchestrator would send,
per SKILL.md lines 119-129: six axes, an overall plan-fidelity score, and — because v0.1
*defines* blocking as "any axis < 7" — the threshold is stated to the rater. No rubric
anchors, no score polarity, because v0.1 supplies neither. **Do not improve this prompt;
the omissions are the thing under test.**

`raters/v0.2.md` is the Phase 7 template shipped verbatim in v0.2: severity definitions,
explicit polarity, required sections, and no mention of the threshold.

`raters/_extraction.md` is appended to **both** arms identically so verdicts can be parsed
mechanically. It adds no evaluative guidance and no threshold to either side.

### What is reported

- **Catch rate on seeded defects** — of the runs on known-bad variants, how many blocked.
- **False-block rate on correct code** — a gate that blocks everything is worthless.
- **Score dispersion on identical input** — the same artifact rated N times, showing how
  much of a numeric threshold's verdict is the artifact and how much is sampling noise.

Gates are applied to each arm's own output, as shipped: v0.1 passes iff
`overall >= 8.5 AND every axis >= 7`; v0.2 passes iff there are zero BLOCKING findings.
An unparseable response is counted as no data, never as a pass.

## Reading the results honestly

Three confounds that no amount of running fixes, and which any writeup must state:

1. **v0.2 changed the flow, the planner model (Opus → fable), and the scope (Rails →
   generic) at once.** A head-to-head measures all three together. Isolating the structure
   needs ablation arms — v0.2 minus the plan critique, v0.2 minus the mechanical gate —
   which the harness supports by adding a flow directory with those sections removed.
2. **Genericity cannot be A/B'd.** v0.1 does not run on a Go or Node repo, so that is a
   capability check, not a comparison.
3. **The author of v0.2 also wrote the critique that motivated it and this harness.**
   Tier 2's ground truth is mechanical, which limits the damage, but a human should
   blind-grade a sample before anyone quotes a number.

## Layout

```
bench/
  flows/v0.1|v0.2/     pinned plugin dirs — same /dev-loop command, different skill body
  tier1/
    setup-app.sh       builds the pristine app + bare origin
    run.sh             one (flow, task) run -> transcript + results.json
    assert.py          the binary assertions
    tasks/             four task prompts, identical across arms
  tier2/
    seed.py            builds the corpus: one good implementation + seeded defects
    raters/            the two rater prompts + the shared extraction block
    replay.sh          corpus x arm x repetitions
    score.py           catch rate, false-block rate, score dispersion
  results/             gitignored run output
  .work/               gitignored pristine app + bare origin
```
